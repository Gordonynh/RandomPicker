# 随机抽选

> 本仓库是 [Gordonynh/RandomPicker](https://github.com/Gordonynh/RandomPicker)
> 的二次修改版，由 happy 维护。原作者与改动内容见文末「作者与二改说明」。

桌面上的一个小圆钮，按一下抽一个人。

## 怎么用

- **左键点一下** —— 抽一个人
- **左键按住拖** —— 挪动悬浮窗（拖不出屏幕，但可以压在任务栏上）
- **右键** —— 设置菜单

抽中之后：屏幕中央弹出大字，同时 ClassIsland 主界面发一条提醒。两个都能在菜单里单独关掉。

## 名单

纯文本，一行一个名字，**没有引号、没有 JSON**，记事本就能改：

```
张三
李四
王五
```

- 空行和以 `#` 开头的行会被忽略
- 重复的名字只算一个
- **保存后立刻生效**，不用重启

文件位置：右键菜单 → **打开名单文件**。首次运行会自动生成一份带说明的示例。

## 三种模式

| 模式 | 行为 |
|---|---|
| **随机抽选** | 每次都从全部名单里抽，只回避「和上一次是同一个人」 |
| **本轮内不重复** | 抽到的人本轮不再出现；抽完一轮自动开新一轮 |
| **拍照抽人** | 用摄像头拍一张，从检测到的人脸里随机挑一个，裁出人像 |

菜单顶部会显示当前模式和本轮剩余人数。想提前重来，点「开始新一轮」。

随机数直接取自操作系统的熵源（`RandomNumberGenerator`），
不存在「拿时间戳当种子、同一毫秒内连抽拿到同一个人」这种问题。

## 拍照抽人

**应用设置 → 随机抽选** 里有完整设置和「试拍一次」。

> ⚠ **只能检测正对镜头的人脸。** 没有可离线使用的模型能认出后脑勺，背对镜头的人抽不到。
> 用「试拍一次」对着真实场景量一遍再决定用不用——它会打出分辨率、检出人数、各步耗时，
> 并把画了检测框的照片显示出来。

用的是 OpenCV Zoo 的 **YuNet**（232 KB ONNX），靠 ONNX Runtime 跑，两样都随插件打包，
全程离线。所以这个插件包是 4.6 MB，其余几个都只有几十 KB。

在一张几十人的合影上实测，单次推理检出 97 张脸、耗时 63 ms；
作为对照，Windows 自带的人脸检测整帧只检出 4 张，分块放大到 58 张要 736 ms。

几个可调项：

- **摄像头保持时间**（默认 120 秒）：打开摄像头要 0.2~1.5 秒，首帧还得再等一会儿；
  开着的时候每帧只要几十毫秒。所以抽完先不关，连着抽几乎是瞬时的。
  代价是这期间摄像头指示灯亮着，到点自动关掉。设成 0 就是用完立刻关，页面上也有「立刻关闭」。
- **人脸分数阈值**（默认 0.50）：0.50 检出 97 人，0.70 只剩 60 人，
  而 **OpenCV 默认的 0.90 只有 1 人**——那个默认值在人多的场景下完全不能用。
- **分块检测**（默认关）：把画面切块各检一遍再合并，能从 97 提到 132，代价是每块一次推理。
- **保存原图**（默认关）：合影是在场者的影像，不开的时候整帧只在内存里待到裁完就丢。

### 回避最近抽过的人

独立随机的意思是上一次抽了谁对这一次毫无影响——30 个人里连着两次撞上的概率是 1/30，
抽十几次几乎一定会遇到，看着就很像「坏了」。

所以拍照模式会**回避最近抽过的几个人**（默认 6 个）。人不会乱动，
所以用人脸在画面里的位置当身份：位置落在最近抽过的那几个附近的，这一轮先不抽。
避开之后一个都不剩时退回全体重挑——宁可重复也不能抽不出人。设成「不回避」就是纯独立随机。

回避记录只在内存里：摄像头一挪、人一换座位，那些坐标就没意义了，
存进配置反而会把过时的回避带到下一次开机。

### 混入文字抽选

拍照模式下可以设一个概率，按这个概率改成按名单抽名字。一直是照片会腻，
偶尔蹦一个名字更有意思，也照顾到没被拍进画面的人。

**文字抽选可以用单独一份名单**（`名单-文字.txt`），和拍照那套完全隔离：
想让文字抽选只覆盖某几个人时不必动主名单。
两份名单共用同一套「本轮已抽」状态——名单隔离是为了圈定范围，不是各记各的进度。

## 抽选动画

点一下之后不是直接蹦出名字，而是先「抽」给你看。**动画不参与抽选**：
中选者在点下去的那一刻就已经定好了，换任何样式、把时长拖到多长，概率都一样。

右键菜单 → **抽选动画**里切换，五种：

| 样式 | 效果 | 默认时长 |
|---|---|---|
| **无动画** | 抽完直接出结果 | — |
| **滚动名字** | 中央大字按名单顺序循环换名字，先快后慢地减速后定格 | 4 秒 |
| **CSGO 开箱** | 名字方块横向滚过，指针停在中间那一块上（停在方块内的哪个位置是随机的） | 4 秒 |
| **老虎机** | 逐格抽字，每格从「还有可能」的字里挑 | 1.5 秒/格 |
| **拼多多转盘** | 指针先停在两格的缝上晃一下，再往左或往右挪半格滑进去；高亮始终跟着指针走 | 6 秒 |

**四种动画都是非线性的**：开局飞快、越到后面越慢，停下来的那一下有缓冲。
匀速滚动看着像在拖进度条，减速才像真的在「抽」——快到看不清楚，慢到能读出名字。

**收尾都会停一下。**四种样式在动作停下之后都留了 **0.8 秒定格**：
滚动名字停在名字上、方块停在指针下、板面拼完、指针停在格子上，各自静止那么一会儿
再切去出结果。没有这一段的话最后一帧刚出现就被结果顶掉，等于白演。

这段定格**不算在动画时长里**：动画把动作演完就结束了，之后画面保持最后一帧不动。
它和「动画时长」分开，是为了让减速曲线铺满整段动作——挪进去的话关键帧会整体前移，
减速只演得出一半，看起来像「猛地冲过去然后干等」。

四个时长在 **应用设置 → 随机抽选 → 抽选动画** 里调，只对当前选中的那个样式生效。

几个说明：

- **老虎机的格数**取当前名单里最长名字的字数，夹在 2~4 格。名字短的人抽中时，
  末尾几格留空——不会拿别人的字去填，那样板面和中选的人就对不上了。
  名单里一旦有**超过四个字**的名字，这个样式会自动改用滚动名字（超出的字显示不出来）。
- **老虎机里「已经没得抽」的格子不转。**候选字只剩唯一一种可能时（比如名单是「张三、李四」，
  第一格定下「张」之后第二格只剩「三」），再转也是同一个字一闪一闪，看着像卡住了。
  这些格子不占时间，而且**要等到真正在转的格子全部停稳的那一刻才一起亮出来**——
  提前显示会把答案剧透掉，第一格还在滚的时候就知道是谁了。
  从某一格起往后全是这种格子时，动画就此提前收尾，比配置的时长短。
- **滚动名字的帧序就是名单循环展开的一段**：中选者排在最后一帧，他前面依次是名单里排在他
  前面的那些人，滚到他身上正好停住。名字一个挨一个滚过去才看得出「越滚越慢」——
  早先是每一帧从别人里随机挑，名字在乱跳，换帧间隔明明在变长，画面却看不出节奏。
- **CSGO 的指针停在方块内的哪个位置是随机的**，不会每次都压在名字正中；但指针底下
  永远是中选者那一块，不会停错。
- **转盘最多画 12 个扇区**，人不够时不重复放。中选者一定在盘面上。
  指针停在边界之后往哪边滑是 50/50，但最终停在哪一格是确定的——就是中选者。
  **亮起来的那一格永远是指针指着的那一格**，指针没滑到之前中选者不会先亮。
- 动画期间**再点不会重抽**，钮上显示 **「跳」**，点一下直接跳到结果（中选者早就定好了，
  跳过只是不看表演）。不点的话动画自己播完，钮自动恢复成剩余人数。
- 最后定格的那一下之后，才轮到「停留 X 秒」计时：**那个设置只管结果停多久，不影响动画时长**。
- 拍照抽人不播动画——抽的是人脸，没有名字可滚。

不想看动画就在右键菜单里选**「无动画」**，那是唯一能关掉它的地方——
这个动画属于抽选本身，所以它**不受 ClassIsland 的「动画级别」管制**：
宿主那个开关管的是它自己的界面过渡，把它设成「禁用」不会让抽选也变得没有动画。

### CSGO 名字品质

CSGO 开箱那一段里，每个方块下面有一条品质色带，中选的那一块还会按品质给整块染上底色，
停稳之后那一块最亮——「开出来了」这件事由它自己说。滚动中其余方块的底色也按各自的**装饰**
品质浅染一层，颜色一路扫过去，但都比中选那一块淡；停稳前指针下那块用的是装饰品质，
不是中选者的，所以不会提前剧透。

五档，默认照搬 CS:GO 的开箱分布：

| 品质 | 颜色 | 默认概率 |
|---|---|---|
| 军规级 | 蓝 | 79.92% |
| 受限级 | 紫 | 15.98% |
| 保密级 | 粉 | 3.20% |
| 隐秘级 | 红 | 0.64% |
| 罕见特殊物品 | 金 | 0.26% |

概率在 **应用设置 → 随机抽选 → CSGO 名字品质** 里调，五个数字是**相对权重**，
不必凑成 100——调的时候不用一边拖一边心算总和。设置页下面会实时换算成
「约 1/N 抽见一次」，比一串百分数直观。

两件事要说清楚：

- **品质只影响颜色，不影响抽到谁。** 中选者在点下去的那一刻就定好了，品质是事后摇的装饰。
  这一条有单测钉着：把权重全压给金色，中选者和默认分布下**完全一样**。
- **品质只出现在动画里。** 动画结束后的中央大字和 ClassIsland 提醒里不显示品质——
  抽的是人，不是皮肤。

## 其他设置

- **悬浮窗大小**：小 / 中 / 大
- **抽中之后**：中央大字开关、ClassIsland 提醒开关、大字停留时长（1.5 / 2.5 / 4 秒）
- **隐藏悬浮窗**：藏起来；想叫回来重启 ClassIsland

位置、模式、各项开关都会自动记住——位置是拖到哪里就记哪里，一拖就存，不用手动保存。

**屏幕分辨率换过之后，位置会回到默认的右下角。** 记下位置的同时也记下了当时那块屏幕的
尺寸，下次启动时对不上（换了显示器、改了分辨率、接了投影）就当作旧的坐标不再适用。
判据是「当前所有屏幕里还有没有一块尺寸相同的」，所以双屏时把悬浮钮摆在副屏上、
只换了主屏的分辨率，位置不会被动。

## 置顶

悬浮窗和中央大字都会被持续按在最顶层：除了设 `Topmost`，还会加上
`WS_EX_TOOLWINDOW`（不进 Alt+Tab）和 `WS_EX_NOACTIVATE`（不抢焦点），
并由定时器反复调用 `SetWindowPos(HWND_TOPMOST)` 顶回去。
全是文档化的公开 API，不改系统设置，也不碰别的进程。

## 开发

### 编译环境

插件工程里的 `ProjectReference` 写的是 `..\..\ClassIsland.Core\ClassIsland.Core.csproj`，
所以源码必须放在 ClassIsland 源码树的 `plugins/` 目录下才能编译。不想复制一份的话，
Windows 上可以建一个目录联接，源码仍然留在自己的仓库里：

```
mklink /J ClassIsland\plugins\RandomPicker <插件仓库路径>
```

- 插件本体是 net8.0，用 .NET SDK 8 就能编。
- 宿主 ClassIsland 仓库的 `global.json` 要求 .NET SDK 9 及以上，编宿主时需要另装。
- 插件引用的 `Microsoft.Windows.SDK.NET` / `WinRT.Runtime` 来自
  `microsoft.windows.sdk.net.ref` 这个 NuGet 包。它是框架引用包（`DotnetPlatform` 类型），
  不能写成 `PackageReference`，只能用 `PackageDownload` 拉取。本机缓存里没有它时，
  编译会报「未能解析此引用：Microsoft.Windows.SDK.NET」。

### 测试

```
dotnet test plugins/RandomPicker/tests/RandomPicker.Tests/ClassIsland.RandomPicker.Tests.csproj -c Release
```

测试工程在 `tests/RandomPicker.Tests`，xUnit，覆盖名单解析与三种抽选模式、设置读写与损坏配置、
人脸几何计算与边界、回避状态、人脸框去重，以及四种抽选动画的排片表
（换帧时刻表、方块轨道几何、老虎机格数与候选字收敛、转盘的指针归属与边界滑动、宿主动画开关的降级判据）。

**测试必须从源码树这一侧发起编译**（用上面那条 `plugins/...` 路径，或用目录联接的路径）。
直接对着插件仓库的真实路径运行会因为 `..\..\ClassIsland.Core` 解析不到而失败，
原因和主项目只能在源码树里编译是同一个。

运行 `dotnet test` / `dotnet build` 时的**当前目录不要落在 ClassIsland 源码树里面**：
宿主根目录的 `global.json` 要求 .NET SDK 9，而编插件只需要 SDK 8。
把命令的当前目录放在插件仓库自己这一侧、参数里写联接路径，就能同时满足两条：

```
cd <插件仓库>                                            # 当前目录在源码树外
dotnet test <源码树>/plugins/RandomPicker/tests/RandomPicker.Tests/ClassIsland.RandomPicker.Tests.csproj -c Release
```

相机 I/O 和模型真实推理不在这批测试范围内：它们需要真实摄像头和原生推理库，
只能在应用内「设置 → 随机抽选 → 试拍一次」中人工验证。

### 界面层的测试

界面不是「没法测」——用 Avalonia 的无头平台可以在没有显示器的环境里把窗口和控件
真的建出来、量出来、按真实尺寸渲染成位图，再把像素读回来检查。
测试工程里 `HeadlessTestApp.cs` 就是这个环境（无头 + Skia；没有 Skia 的话渲染结果恒为空白，
「有没有画出东西」这条断言就失去意义了）。

这一层专门挡那些**编译期完全不设防**的问题：过渡或动画漏写 `Property`、
自绘控件忘了覆写 `MeasureOverride`（量出来 0×0，画面上什么都没有而且不报错）、
几何算成 NaN 让整帧空白。它们不会被编译器和纯逻辑测试发现，
只在「控件真的被建出来」的那一刻现形——曾经就这么漏过一个上线即崩的 bug。
四种动画的**画面**同理：排片表（要演什么、演多久、指针最终落在哪一格）全部有单测钉着，
但实际观感需要人工把五种样式各抽一遍才能确认。
